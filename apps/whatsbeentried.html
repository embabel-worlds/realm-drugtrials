How it works

The data, and how fresh it is

Nothing here is a copy. Each search asks ClinicalTrials.gov for the disease you typed, live, after rewriting your words into the registry's own search syntax; the answer is held for six hours, and the registry's own data timestamp is shown beside it. A search reads up to ten pages of 1,000 trials, and when the registry has more it says so (coverage PARTIAL_PAGE_CAP) rather than presenting a prefix as the whole. Status, age-cohort and "open to" filters are sent to the registry, so a narrowed search fetches only the trials it shows. Sponsors resolve to company profiles through realm-research.

The queries that run

Landscape (lens trial-landscape, over the view DiseaseTrialRuns):

MATCH (run:DiseaseTrialRuns {registryQuery: $query})
MATCH (run)-[:HAS_COVERAGE]->(coverage:TrialCoverage)
OPTIONAL MATCH (run)-[:RETURNED]->(trial:ClinicalTrial)
WHERE trial.overallStatus = $status AND $sex IN trial.openTo AND $ageGroup IN trial.ageGroups
RETURN run.dataTimestamp, run.sourceTotal, coverage.state, trial.nctId, trial.title, trial.overallStatus, …
ORDER BY trial.lastUpdated DESC, trial.nctId ASC

(each WHERE clause is present only when its filter is set).

Themes (lens trial-themes):

MATCH (scope:DiseaseScope {registryQuery: $query})-[:HAS_TRIAL_SEARCH]->(run:TrialSearchRun)
MATCH (run)-[:RETURNED]->(trial:ClinicalTrial)
RETURN cluster(trial.title, $topics) AS clusters, summarize(trial.title, $brief) AS digest, count(trial) AS trialCount

Sponsors (lens trial-sponsors):

MATCH (scope:DiseaseScope {registryQuery: $query})-[:HAS_TRIAL_SEARCH]->(run:TrialSearchRun)
MATCH (run)-[:RETURNED]->(trial:ClinicalTrial)
OPTIONAL MATCH (trial)-[:SPONSORED_BY]->(company:CorporateEntity)
RETURN trial.nctId, trial.sponsor, trial.sponsorClass, company.ultimateOwner, company.country, company.industry

What an empty panel means

An empty trial list means the registry holds no trial matching the disease and the filters you set, not that no research exists: other registries and unregistered work are not searched. A failed search shows an error, never an empty list. An empty sponsor-owner column means the sponsor's name could not be resolved to a company, not that it has no owner. An empty themes panel means there were no trials to characterise.

What this did that a conventional stack could not

A conventional site would mirror the registry nightly and filter its copy. Here the question is the query: the filters reach the registry itself, the result joins company profiles from another source in the same graph query, the themes are computed by the engine over exactly the rows shown, and every answer carries its own coverage and source timestamp. Nothing is stored afterwards.
